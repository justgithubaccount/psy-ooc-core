Psyche: Object-Oriented Consciousness Core
==========================================

> Моделирование психики как системы объектов, состояний и развития.
> Построено на принципах психодинамики, объектных отношений и архитектуры ИТ.

О проекте
---------

Psyche / OOC-Core — это фреймворк, симулирующий внутреннюю психическую систему человека.
Он строится на метафоре: "психика — как код, внутренние объекты — как классы, события — как вызовы методов".

Ядро моделирует:
- TheSelf — центральное Я
- Ego — его стадийное развитие
- InternalObjectMap — карту внутренних объектов
- DefenseSystem — защитные механизмы
- GrowthEvent — события, влияющие на сознание

## Статус реализации

Ядро базовых процессов работает: события проходят через `Ego`, меняют устойчивость
и двигают стадию развития. Часть объектов модели уже описана, но к потоку событий
пока не подключена.

**Работает сейчас**

| Объект | Что делает |
|---|---|
| `TheSelf` | корневая структура, собирает подсистемы, принимает события |
| `Ego` | обрабатывает событие: меняет `stability`, двигает стадию, срывается в `DISRUPTION` |
| `GrowthEvent` / `EgoStage` | событие и пять стадий: MERGED → DIFFERENTIATION → INTEGRATION → COHERENCE, плюс DISRUPTION |
| `LifeSimulation` | прогон произвольного числа шагов со структурированной историей |
| HTTP API | `GET /self`, `POST /event`, `POST /self/reset` |

**Описано, но не подключено к потоку событий**

| Объект | Что умеет | Кто вызывает |
|---|---|---|
| `TrueSelf` | `increase_vitality()`, `decrease_vitality()` | никто |
| `FalseSelf` | `adopt_role()`, `disconnect_from_true_self()` | никто |
| `DefenseSystem` | `activate_defense()` | только чтение в `GET /self` |
| `RelationManager` | связи между внутренними объектами | никто |
| `HistoryManager` | история развития | никто |

Это и есть ближайший шаг — см. [ROADMAP.md](./ROADMAP.md). Цепочка «травма → напряжение
и контроль → аватар → истинное Я угасает» из
[манифеста проекта](https://github.com/justgithubaccount/intro-justgithubaccount)
на сегодня описана объектами, но не соединена в работающий процесс.

## Быстрый старт

Проект собирается через [uv](https://docs.astral.sh/uv/).

```bash
uv sync                              # поставить зависимости
uv run pytest                        # тесты
uv run ooc simulate --steps 20       # симуляция с выводом в консоль
uv run ooc simulate --steps 20 --json  # то же, структурированной историей
uv run uvicorn ooc.api.main:app --reload
```

Через Makefile: `make install`, `make test`, `make lint`, `make check`, `make run-server`.

В Docker:

```bash
docker build -t ooc-core . && docker run --rm -p 8000:8000 ooc-core
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/self` | текущее состояние: стадия, устойчивость, активные состояния и защиты |
| `POST` | `/event` | отправить событие: `name`, `impact` в диапазоне [-1, 1], `type_` |
| `POST` | `/self/reset` | сбросить психику сессии в начальное состояние |

`type_` принимает `support`, `frustration`, `trauma`, `success`, `loss` — те типы,
которые умеет разбирать `Ego`. Остальные отклоняются с кодом 422.

Заголовок `X-Session-Id` разделяет психики: разные значения — независимые экземпляры,
по умолчанию `default`. Состояние живёт в памяти процесса и не переживает рестарт.
