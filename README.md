# Psyche: Object-Oriented Consciousness Core

> Моделирование психики как системы объектов, состояний и развития.
> Построено на принципах психодинамики, объектных отношений и архитектуры ИТ.

## О проекте

Psyche / OOC-Core — это фреймворк, симулирующий внутреннюю психическую систему человека.
Он строится на метафоре: «психика — как код, внутренние объекты — как классы,
события — как вызовы методов».

Проект — часть замысла, описанного в
[манифесте профиля](https://github.com/justgithubaccount/intro-justgithubaccount):
модель психики как компонент ИИ-агента.

## Быстрый старт

Сборка через [uv](https://docs.astral.sh/uv/).

```bash
uv sync                                 # зависимости
uv run pytest                           # тесты
uv run uvicorn ooc.api.main:app --reload  # API на localhost:8000
uv run ooc simulate --steps 20          # симуляция жизни
uv run ooc simulate --steps 20 --json   # то же, структурированной историей
```

Через Makefile: `make install`, `make test`, `make lint`, `make check`,
`make run-server`, `make simulate`.

В Docker:

```bash
docker build -t ooc-core . && docker run --rm -p 8000:8000 ooc-core
```

Swagger — на `http://localhost:8000/docs`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/self` | текущее состояние: стадия, устойчивость, активные состояния и защиты |
| `POST` | `/event` | отправить событие: `name`, `impact` в диапазоне `[-1, 1]`, `type_` |
| `POST` | `/self/reset` | сбросить психику сессии в начальное состояние |

`type_` принимает `support`, `frustration`, `trauma`, `success`, `loss` — то, что умеет
разбирать `Ego`. Остальное отклоняется с кодом `422`.

Заголовок `X-Session-Id` разделяет психики: разные значения — независимые экземпляры,
по умолчанию `default`. Состояние живёт в памяти процесса и не переживает рестарт.

```bash
curl -X POST localhost:8000/event \
  -H 'content-type: application/json' \
  -H 'X-Session-Id: alpha' \
  -d '{"name": "Поддержка", "impact": 0.3, "type_": "support"}'
```

## Сущности ядра

| Объект | Роль |
|---|---|
| `TheSelf` | центральное Я, собирает подсистемы и принимает события |
| `Ego` | развивающееся Я: стадии и устойчивость |
| `GrowthEvent` / `EgoStage` | событие и пять стадий развития |
| `TrueSelf` / `FalseSelf` | подлинное и ложное Я |
| `InternalObject` | образ значимого Другого |
| `InternalObjectMap` | вся внутренняя карта |
| `StateManager` | активные состояния |
| `DefenseSystem` | психологические защиты |
| `RelationManager` | связи между внутренними объектами |
| `HistoryManager` | история сознания |

Стадии развития Эго:

```
MERGED → DIFFERENTIATION → INTEGRATION → COHERENCE
                     ↓
                DISRUPTION
```

## Статус реализации

Ядро базовых процессов работает: события проходят через `Ego`, меняют устойчивость
и двигают стадию. Часть объектов описана, но к потоку событий пока не подключена.

**Работает**

- `TheSelf` принимает события, `Ego` их обрабатывает;
- переходы стадий и срыв в `DISRUPTION`;
- `LifeSimulation` — прогон на произвольное число шагов со структурированной историей;
- HTTP API и CLI.

**Описано, но не подключено**

| Объект | Что умеет | Кто вызывает |
|---|---|---|
| `TrueSelf` | `increase_vitality()`, `decrease_vitality()` | никто |
| `FalseSelf` | `adopt_role()`, `disconnect_from_true_self()` | никто |
| `DefenseSystem` | `activate_defense()` | только чтение в `GET /self` |
| `RelationManager` | связи между объектами | никто |
| `HistoryManager` | история развития | никто |

Цепочка из манифеста — «травма → напряжение и контроль → аватар → истинное Я угасает» —
на сегодня описана объектами, но не соединена в работающий процесс.
Ближайшие шаги и открытые вопросы о модели: [ROADMAP.md](./ROADMAP.md).

## Инвариант поведения

Ядро описывает развитие Я, и рефакторинг не должен менять это поведение — только
читаемость кода. Инвариант закреплён тестом: прогон `LifeSimulation` на 30 шагов
с `random.seed(42)` сверяется с эталоном из `tests/golden/` шаг в шаг.

Падение `tests/test_golden_behavior.py` означает изменение модели, а не оформления.
Осознанное изменение модели требует обновления эталона отдельным коммитом — тогда
дифф покажет, как именно поменялось поведение психики.

## Структура

```
src/ooc/
├── core/        # TheSelf, Ego, GrowthEvent, защиты, внутренние объекты
├── api/         # FastAPI: приложение, маршруты, зависимости
├── cli/         # команда ooc

```

## Стек

Python 3.10+ · FastAPI · Pydantic v2 · Typer · uv · Docker · pytest · ruff · black

`docker-compose.yml` дополнительно поднимает PostgreSQL и Redis: переменные
`DATABASE_URL` и `REDIS_URL` проброшены как задел под персистентность, но кодом
пока не используются.
